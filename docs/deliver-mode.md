# Deliver 模式

面向「让 agent 交活」的场景，与 Regular 的差异集中在可见内容与收尾方式。模式本身的状态与切换流程见 [modes.md](modes.md)。

## 可见内容

- 思考内容、工具调用过程、模型的自由正文都不展示。
- 运行期间只在记录末尾显示 `Working...` 和已耗时。
- 卡在 `request_user_decision` 上等用户作答时不显示 `Working...`，那段时间也不计入耗时，用户交卷后从原来的读数继续。
- 每次任务必须以一个交付工具的调用收尾；普通的 Read / Edit / Write / Bash 仍照常执行，只是界面上看不到。

## 交付结果

交付结果以结构化块呈现：

| 工具 | 展示 |
| --- | --- |
| `report_success` | 完成描述、交付产物与建议的下一步 |
| `report_failure` | 失败原因与调整建议 |

## 选择题卡

`request_user_decision` 在聊天记录里渲染成选择题块，支持是否题、单选题、多选题，可一次问多个问题。

- 工具会阻塞当前 run，等用户在卡片上作答后把答案作为工具结果交回模型，同一轮继续。
- 点击提交后如果请求失败，卡片回到可提交状态并在聊天记录里附一条错误，可以重新提交。
- 是否题用按钮，单选题用 radio group，多选题用 checkbox group。
- 选项的 `label` 只放内容本身，`description` 作为介绍在鼠标悬停的 tooltip 里展示。
- 每个问题可以带 `show_other_choice`，默认展示一个「其它」项，用户选中后可以自己输入。这一项由界面统一追加，工具描述里也明确要求模型不要自行创建其它选项，否则会出现两个「其它」。

## 交付产物

`report_success` 的 `artifacts` 是交付产物路径列表，可以是网页链接（`http://` / `https://`）或本地绝对路径。

- 前端在「交付产物」下逐条列出。
- 点击网页链接交给系统浏览器打开，点击本地路径用系统默认应用打开。
- 本地路径的打开权限限制在 `$HOME` / `$TEMP` / `$DOWNLOAD` / `$DOCUMENT` / `$DESKTOP` 与 `/tmp` 这些目录下（见 `src-tauri/capabilities/default.json` 里 `opener:allow-open-path` 的 scope），scope 之外的路径会提示打不开。

## 卡片配色

系统通知、确认、选择题、交付结果跟用户消息用同一套版式，只用底色区分：

| 内容 | 底色 |
| --- | --- |
| 系统通知、选择题 | 浅蓝 |
| 确认待回答 / 确认后 / 取消后 | 浅黄 / 浅绿 / 灰色 |
| 交付成功 / 交付失败 | 浅绿 / 浅红 |

交付工具实现在 `sidecar/src/deliver.ts`。
