# 会话

## 存储

会话由 sidecar 记录，一个会话一个 JSONL 文件，存在 `~/.mypi/sessions/`（`MYPI_SESSIONS` 可改目录）。

- 文件名就是会话 id，形如 `20260205-102231-a1b2c3d`：前缀是本地时间，末尾七位随机十六进制（与 git short SHA 同宽）避免同一秒重名。
- 文件里的时间戳是 epoch 毫秒，所以 `/sessions` 里的顺序按 id 倒序排。
- 文件权限 0600。

## 记录内容

第一行是会话头，记下 id、开始时间、模式、工作目录、provider 与 model。之后每行一条记录，存的是 agent 侧真实的消息对象：

- 用户消息
- assistant 消息（去掉 thinking 部分，思考内容不落盘）
- tool result，额外带 `durationMs`，从 `tool_execution_start` 到 `tool_execution_end` 计时，供前端回看时显示工具耗时；早期写入的旧记录没有这个字段，回看时不显示耗时
- 运行错误
- 模式、工作目录的变更

这份记录同时也是排查模型输出的依据：原始 JSONL 里的转义换行就是模型当时返回的文本。

## 切换与重建

每条会话的聊天记录与模型上下文都从这份文件重建，会话之间完全独立：在 A 里聊到一半切到 B，A 的文件不动；切回 A 时历史照旧，接着发消息就追加在 A 的同一份文件里。

切换时 sidecar 会：

1. 按消息里的 `toolCall` / `toolResult` 配对校验历史，把当前模式不支持的工具调用、以及缺少配对结果的残缺调用剔掉。
2. 把工具集与系统提示词按当前配置重建，避免模型看到不存在的工具或悬空的工具结果。

会话记录的模式会跟着恢复，但系统提示词与工作目录仍用当前配置。

每次 `/clear` 或 `/new` 结束当前会话并开一个新的；应用重启也算新会话，不会自动恢复上一次的上下文。没有产生任何记录的会话不建文件，也不出现在列表里。

## 会话列表页

`/sessions` 不在聊天记录里输出列表，而是切到一个独立页面：

- 左上角是 `SESSIONS` 标题，下面列出最近的 50 个会话。
- 每行是会话 id、是否当前会话、右侧的相对时间（悬停可见确切时间戳）与首条用户消息的摘要。选中的一行（鼠标划过即选中）用主题色淡底高亮，样式与定制入口见 [theming.md](theming.md) 的 `.mypi-session-row`。
- 底部左侧的搜索框是 shadcn 的 `InputGroup` 加前置搜索图标，整行默认收起为零高度，敲键盘直接展开并过滤列表，顶部没有额外的状态栏。输入停顿 150ms 后才发一次搜索请求，避免每个按键都读一遍会话文件。
- 键盘 ↑ / ↓ 移动选中行、Enter 切换；鼠标划过某一行高亮也跟着过去、单击直接切换。
- 搜索框里输入关键词按会话 id 与 user / assistant 正文过滤列表，Esc 先清空关键词、关键词为空时再返回聊天页。

切换后聊天记录换成该会话，并追加一条 `SESSION` 提示说明接下来会写进哪个会话。`/sessions <序号>` 或 `/sessions <id 前缀>` 仍可直接在当前页切换，不必先打开列表页。

消息树与分支详见 [jump-and-branching.md](jump-and-branching.md)。
