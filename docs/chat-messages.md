# 聊天记录与消息渲染

## 数据模型

聊天记录是一个 `AgentMessage` 列表，前端直接跟 agent-core 的消息生命周期走，不做 delta 累加。

| 事件 | 前端行为 |
| --- | --- |
| `message_start` | 开一条新的 assistant 气泡并置为思考态 |
| `message_update` | pi-agent-core 带的是整条 assistant 消息的完整快照（`event.message`），sidecar 只把文本投影成 `assistant_text`，前端整体替换气泡文本 |
| `message_end` | 用最终消息收尾 |
| `tool_execution_start` | 工具单独成行 |

整体替换的做法既不会把一段文本拆成两个气泡，也没有拼错或漏拼的可能。

## 思考内容

- 思考阶段前端只拿到 `message_start` 的思考态。
- `thinking_delta` 在 sidecar 里就被丢掉，思考内容不会离开 sidecar 进程。
- 界面上只显示 `Thinking...` 与已耗时。

## 错误与中止

| 情况 | 呈现 |
| --- | --- |
| 模型报错 | `message_end` 带 `stopReason: "error"` 与 `errorMessage`，显示在气泡里 |
| sidecar 自身启动失败 | 走 `run_error` 事件 |
| 指令执行失败（如 `/cd` 指向不存在的目录） | 独立的 `error` 行，浅红底，不挂在用户消息内部 |
| 用户主动中止 | 同上的独立 `error` 行，文本是「已中止」 |

文本为空又没有报错的气泡会被丢掉，工具调用轮就是靠这一条丢掉的，不会再有空白占位气泡。

## 工具行

工具调用占一条整宽底色，行内左侧是加粗的工具名与主要参数，右侧右对齐一个实时耗时，基底样式是 `px-4 py-3`、与消息相同的字体与 15px/行高。

状态底色：

- 运行中：浅蓝
- 成功：浅绿
- 失败：浅红

参数展示：

| 工具 | 显示 |
| --- | --- |
| `Bash` | `耗时/超时`，超时取工具参数，缺省 120 秒 |
| `Read` | 有 `offset` / `limit` 时拼成 `path:起-止` |
| `Edit` | 只显示路径 |
| `Write` | 路径后附内容字节数 |
| 未知工具 | 工具名加紧凑 JSON 参数，最多 400 字符 |

耗时在 1 秒以内每 0.1 秒刷新、超过 1 秒后每 1 秒刷新，工具结束时定格在最终值。切换会话回看历史时，工具行用会话记录里的 `durationMs` 显示同样的定点耗时，旧记录没有这个字段就不显示。

工具失败时在那行下面追加一块整宽的浅红错误详情，展示 sidecar 返回的完整输出，超时也走同一块（sidecar 在输出里附了 `[已超时 ...ms 并终止进程]`）。

前端的流式更新通道（`tool_execution_update`）已经就绪，但当前四个工具都不上报中间结果，所以只有耗时是活的，输出只在失败时展示。

系统消息、确认卡、交付卡与选择题卡跟用户消息共用一套版式（整宽、相同内边距与 15px/行高，标题一行、正文 `mt-1`），只用底色区分，详见 [deliver-mode.md](deliver-mode.md)。
